# destbreso

The GitHub profile repository: its README is the profile at github.com/destbreso, and the same repository is a GitHub Pages site (destbreso.github.io/destbreso), an analyst's report of how the author works, every figure generated daily from commit data.

Read first: `README.md` (the profile), `.github/scripts/README.md` (the data pipeline: tokens, what private work is counted, the timezone), `tools/README.md` (the hero and the robot, made by hand rather than daily), then `index.html` and `assets/` (the report).

## Identity and look

- The profile's angle is the mathematician who builds: algorithms, craft, first principles. The current role is a small fact chip, never the framing. Same person as destbreso.com, another facet of him. The README reads as him talking, in the first person, plainly, and it leads to destbreso.com in context (the circuit, the robot, the lab, the blog), never as a call to action.
- Blueprint dark (`#0b0e14` with a grid), one restrained accent, plotter cyan `#4dd4e0`, and the system monospace; deliberately not destbreso.com's terminal green. Where a figure splits public from private work, private is purple (`--c3`). The one exception is the robot, which keeps its own colours (cream shell, black glass face, green eyes): it is the site's robot, not a figure of this report.
- No third-party widgets in the README (stats cards, trophies, streaks, typing banners, the snake, visitor counters, rows of badges): everything shown is generated here or comes from the author's own site. No figure carries a label naming its trick; data labels a reader needs (a project's name, a month) are fine.
- `01 · Building` links only to public repositories or public sites: a private repository is a 404 for every visitor.

## The figures

- The hero (`assets/hero-dark.gif`, `assets/hero-light.gif`) is the name beside a Game of Life circuit that really runs: a Gosper gun, a reflector and an eater, written in the site's Glider ISA, compiled and stepped by destbreso.com's own engine (`tools/hero/frames.ts`, run from a checkout of the site's repository). It is one period of the circuit, so the GIF's last frame leads into its first and the loop has no seam; a GIF because it plays in every GitHub client. The tagline "first principles, from proof to production" stays: the author asked to keep it. Rebuilt by hand (`tools/hero/build.sh`), not daily.
- The robot (`assets/robot.svg`) is destbreso.com's robot, drawn in pixels from its 3D model's own measurements and materials (`tools/robot/`). It has a corner of its own, beside the lines that invite to the site, and never acts on a figure: a robot walking a chart was rejected as absurd. It is alive and never seems to loop: a four-minute script drawn from a deck of behaviours (reading, a fly, dozing, hearts, a wink, driving on its wheels), none twice in a row, and now and then its face shows the site's mark with the cursor blinking. It has no name and is not given one: not in the figures, captions, alt text, docs or commits of this public repository. Its lines hint and never tell how it is found on the site (destbreso.com's rule on its secrets).
- `year.svg` and `year-light.svg` (`generate-year.py`) are the README's year: a thread a project for the last 52 weeks, in the order the projects started, thicker in the weeks they took more work, this week lit at the right; public projects named, private work in violet. It replaced (2026-11-07) a column a week walked by a robot, which said only how many commits, and before it the Fourier signal and the contour map (2026-11-05), which no visitor could read. `assets/year.js` draws the same figure on the page with the same geometry (change one, change both), where pointing at a thread reads its project and the week.
- The heatmap is a whole year folded into a typical week (day by hour), and says so.
- The public and private split is stacked where the form allows it (the blocks, momentum, the projects) and is the threads' colour; the heatmap stays a combined total. The public/private key shows only when there is private data.

## The data

- The per-repository commit aggregation (`/user/repos?affiliation=owner`, then each repository's commits by the author) is the single source of truth: GitHub's contribution calendar leaves private contributions out even with the PAT. `generate-data.py` writes `dist/series.json` (the 52 weeks from a Monday to today, weekly totals and their public share, the daily counts, and a thread a project) and the year figure is drawn from it, which is why `profile.yml` runs the data step first. Every number on the page that has an aggregation behind it (the streak, the momentum, the trend) comes from it; the calendar is only the fallback when the aggregation finds nothing.
- A repository's commits are read up to 5,000 a year (a cap of 500 once cut the busiest repository's older months out), and the window ends today (one that ended a week back once dropped the newest days).
- The Action starts from the last published snapshot, keeping only the files still generated, so a generator that fails one day leaves the day before's file deployed instead of a broken image (the deploy replaces the whole `output` branch). When `data.json` cannot be loaded the page says so and shows nothing: it never fills in made-up numbers.
- Languages are bytes of code, markup and styles left out (a few repositories of generated HTML pages once made the stack read 81% HTML).
- Private repository names are never emitted unless the author opts a repository in, and never written in this public code. A thread is named by a topic `thread-<label>` on its repository first (repositories with the same label share one thread, so a project split across repositories reads as one), then by a public repository's own name, then by a private repository's website from its About, host and path (the site's own repository shows as destbreso.com, its posts' as destbreso.com/blog); a private repository with neither stays unnamed. Client work is never opted in. Projects with fewer than eight commits in the year share one thread. Private repositories of other organizations are not read at all.
- The KPIs rebuilt from the aggregation carry no year-over-year delta (`None`): there is no prior-year pass to compare with honestly, and the page hides a missing delta. Do not compute one from the calendar.
